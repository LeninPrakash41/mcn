// The project `mcn init my-app` creates
query("CREATE TABLE IF NOT EXISTS tasks (id INTEGER PRIMARY KEY AUTOINCREMENT, title TEXT NOT NULL, done INTEGER DEFAULT 0)")

service tasks_api
    port 8080

    endpoint add_task(title)
        if not title
            return {success: false, error: "Title is required"}
        query("INSERT INTO tasks (title) VALUES (?)", (title,))
        return {success: true}

    endpoint list_tasks()
        return {success: true, data: query("SELECT * FROM tasks ORDER BY id DESC")}

test "adding a task without a title is rejected"
    assert add_task("").success == false

test "added tasks are listed"
    add_task("Write the README")
    assert list_tasks().data[0].title == "Write the README"
component AddTask
    state title   = ""
    state message = ""

    on submit
        var result = add_task(title)
        message = "Added!" if result.success else result.error
        if result.success
            notify("Task added", "success")

    render
        card
            card_header "New task"
            form on_submit=submit
                input bind=title label="What needs doing?"
                button "Add" variant="default"
                div
                    text message

component TaskList
    state items = []

    on load
        items = list_tasks().data

    render
        data_table title="Tasks" columns=["title", "done"] page_size=10 views=["table", "list"]

app MyApp
    title "My App"
    layout
        tabs
            tab "Add"   AddTask
            tab "Tasks" TaskList

The agent team

Describe what your team needs. The agents build it and test it.

Behind each build is a team of specialist agents running on Claude. They plan the work, write the app, open every screen in a real browser, and fix what they find, then hand you code you can read.

  1. ResearcherWorks out what an app like this needs: users and roles, records, workflows and rules.
  2. ArchitectPlans the tables, endpoints, screens and navigation, and whether to use SSO and audit logs.
  3. DesignerLays out each screen: what comes first, the wording, and what empty screens say.
  4. BuilderWrites the backend and UI in MCN, checked by the parser and type checker.
  5. QA leadCalls every endpoint, opens every screen in a browser, reviews the screenshots and sends fixes back.

Why it works

A language designed for AI agents, not just people.

Programming languages were built around how people type code. An agent's mistakes are rarely typos: they're changes that quietly break something else. MCN is built so agents can see the whole app and check every change.

Little syntax to get wrong

Indented plain words: service, endpoint, component, test. No braces, imports or framework boilerplate.

Every block means one thing

An endpoint is a route, a component is a screen, amount: float is checked on every call, audit logs every call. No framework to guess.

The whole app on one map

mcn describe lists every table, endpoint, screen and test and how they connect, and flags a screen calling an endpoint that doesn't exist.

Changes that stay where you meant

mcn impact shows what a change reaches and which tests cover it. module blocks own their tables, so agents can work side by side and --module proves each stayed in its own.

Questions

Frequently asked questions.

What kind of language is MCN?

A high-level, interpreted scripting language with dynamic typing, built for applications. You write plain .mcn files with indentation-based blocks and run them straight away. The database, APIs, web and mobile UI, AI and hardware are part of the language, so you don't assemble frameworks first.

How is MCN different from AI app builders?

AI app builders write an app for you and usually run it on their own platform. MCN is a language: the app is two short files you can read, change and review, and the same files become a web app, a phone app and an API. You can still have AI write it, with mcn generate or the agent team, and you deploy it to your own Vercel, AWS or Cloudflare account, or any server.

Does MCN support single sign-on and audit logs?

Yes. A service with auth "sso" signs people in with Okta, Microsoft Entra ID, Google Workspace or another OpenID Connect provider, and current_user() tells endpoints who they are and which roles they have. Adding audit to a service records every call in a tamper-evident log with secrets masked; mcn audit-log verify checks it and mcn audit-log export writes OCSF events for a SIEM. MCN itself isn't a SOC 2 or HIPAA certified service: those certifications belong to whoever runs the app.

Can I deploy to AWS or Cloudflare?

Yes. mcn deploy --target aws builds a container and runs it on AWS App Runner in the region you choose, with HTTPS and automatic scaling. mcn deploy --target cloudflare serves the web app from Cloudflare's edge and runs the API in a Cloudflare container. Both run in your own account. Keep data in PostgreSQL by setting DATABASE_URL.

Is MCN a good fit for forward deployed engineers?

Yes, it's built for that kind of work: turning a customer's problem into a working tool in days, on site. One person can write the backend, the UI and the AI logic in a few files, connect the customer's systems with fetch(), query() and domain packages, and put it online with mcn deploy --target vercel or a Docker zip. agent_run() turns the customer's own functions into tools for an AI agent, and mcn audit plus service auth cover the security review. Everything stays as readable code the customer's team can keep.

Can data annotation teams use MCN?

Yes, for building the tools annotators work in, rather than as an off-the-shelf labeling platform. A team lead can build a custom labeling app quickly: a review queue in a data_table or kanban, forms for labels, classify() and extract() to pre-label items with AI, and people confirming or correcting each one. audit_log() records who labeled what, and the data imports and exports as CSV. Annotators just use the app in a browser or on a phone; they don't need to write code.

Do I need to know another programming language first?

No. MCN reads like a description of what the program does, and every error shows the line, points at the problem and suggests a fix. The student pilot kit goes from a first program to a full-stack app with AI in two sessions. Developers who know another language can usually read MCN code straight away.

Is MCN ready for production?

It's designed for internal tools, client pilots and coursework, and has what those need: token, JWT and SSO sign-in, audit logs, rate limits, security headers, tests next to the code, a security scanner, and deploys to Docker, Vercel, AWS and Cloudflare. For a high-traffic public product, load-test it first, and use PostgreSQL for data that must last.

Which AI models does it use, and where does my data go?

ai() uses Claude by default, or OpenAI or a local Ollama model if you choose. MCN doesn't send your code or data anywhere on its own: AI calls happen only when you set an API key, and send only the prompts your code builds. Without a key, AI functions return mock answers, so code still runs offline, in class or in CI.

Am I locked in?

No. MCN is open source under the MIT license. The UI compiles to standard React and Flutter projects you own and can keep editing, and the backend runs anywhere MCN installs: your laptop, a container, Vercel or a Raspberry Pi.

Can it run on a Raspberry Pi or with an Arduino?

Yes. The same device() code is simulated in Studio and drives Raspberry Pi pins, Arduino and ESP32 boards over USB, or MQTT devices. mcn iot firmware writes the board sketch.

How much does it cost?

Nothing. MCN, Studio, the UI kit and the templates are free and MIT licensed. You only pay for AI usage if you use a paid model, and for hosting if you deploy to a paid plan.
